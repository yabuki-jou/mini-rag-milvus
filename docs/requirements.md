# Mini RAG 需求文档

## 文档说明

本文依据当前源代码和测试反向整理。未确认的产品意图使用 `[ASK USER]`，不得擅自补充。

## 背景与目标

项目用于学习并演示完整 AI 应用链路：文档入库、RAG 检索问答、DeepSeek Tool Calling、LangGraph 状态编排、人工确认、业务数据写入、评测与可观测性。目标是形成可写入简历并通过 Swagger 演示的企业知识库与行政 Agent。项目以个人学习为主，可能供朋友小范围使用，但不以公开多用户网站或生产级企业平台为目标。

## 用户角色

- 学习者/演示用户：创建模拟用户，管理自己的知识库、文档和聊天会话。
- 员工用户：通过与 `User` 一对一关联的员工资料，查询自己的假期数据并创建自己的请假申请。
- 当前 `X-User-ID` 只模拟身份，不是登录或安全认证。
- 当前阶段不需要管理员/普通用户角色；未来可以重新评估。
- 用户显示名称允许重复；未来登录功能使用唯一邮箱和密码认证。

## 非功能需求

- NFR-001：错误响应不得泄露密钥、数据库细节或第三方堆栈。
- NFR-002：相对路径统一以项目根目录解析。
- NFR-003：默认 CPU Embedding，适配 16 GB 学习环境。
- NFR-004：关键逻辑可自动测试，测试不调用真实 DeepSeek。
- NFR-005：API 所有权校验与 Milvus 标量过滤共同保证隔离。
- NFR-006：失败可通过状态、`error_message`、请求 ID 和日志观察。
- NFR-007：业务 SQLite 与 LangGraph Checkpoint 分离；Graph State 只保存可序列化数据。
- NFR-008：模型可见的 Tool Schema 不得包含用户、知识库或员工身份字段。
- NFR-009：工具日志不得保存完整制度正文、Token、密码或模型隐藏推理。
- NFR-010：数据库 Schema 使用 Alembic 演进，并保留现有 SQLite 数据。

## 业务规则

- BR-001：除用户创建和健康检查外，接口要求有效 `X-User-ID`。
- BR-002：知识库所有者只能来自已校验用户。
- BR-003：上传成功与向量化完成是不同状态。
- BR-004：`PROCESSING` 文档不得重复解析或删除。
- BR-005：Chunk ID 由 `document_id | page | start_index | content` 计算 SHA-256。
- BR-006：检索为候选 Top-K → `score >= threshold` → 降序 → 最终 Top-N。
- BR-007：无合格 Chunk 返回“知识库中没有足够依据。”且 `sources=[]`。
- BR-008：来源从 `S1` 开始，并与 Prompt 中 Chunk 顺序一致。
- BR-009：删除范围为 `user_id + kb_id + document_id`；不存在返回 204。
- BR-010：解析失败为 `FAILED`，删除失败为 `DELETE_FAILED` 并允许重试。
- BR-011：删除知识库前必须确认其中不存在文档和聊天会话；只要仍有关联数据就拒绝删除，不自动级联清理。
- BR-012：密码只能以安全哈希形式保存，任何数据库字段、API 响应和日志都不得出现明文密码。
- BR-013：JWT 功能完成后，受保护接口只能使用经过签名、有效期等校验的 Token 身份，不再把 `X-User-ID` 作为可信身份来源。
- BR-014：Access Token 用于访问受保护接口，Refresh Token 只用于换取新 Token；二者必须具有可区分的用途声明和不同有效期。
- BR-015：数据库只能保存 Refresh Token 的单向哈希，不保存 Token 明文；刷新时必须校验会话未撤销且未过期。
- BR-016：退出登录必须撤销当前 Refresh Token 对应的登录会话，撤销后的 Token 不得再次刷新。
- BR-017：Refresh Token 在有效且未撤销期间可以重复换取新的 Access Token；刷新时不签发新的 Refresh Token。
- BR-018：Agent 会话必须同时属于当前用户，并绑定当前用户拥有的一个知识库。
- BR-019：员工资料与 `User` 一对一关联；余额和申请工具只能使用服务端注入的当前员工身份。余额工具由模型提供 `leave_type`，申请列表工具不向模型暴露数量参数并固定返回最近 20 条。
- BR-020：制度检索沿用 Top-K、阈值、Top-N 和 `user_id + kb_id` 过滤规则；无合格 Chunk 时不得编造答案。
- BR-021：请假申请只支持年假和病假；服务端按周一至周五计算整工作日，暂不处理法定节假日和半天假。
- BR-022：开始日期不得晚于结束日期，请假天数必须大于零，年假申请不得超过当前可用余额。
- BR-023：创建申请前必须返回草稿并暂停；拒绝不写业务表，批准后以唯一幂等键最多写入一次。
- BR-024：Graph State 不得保存 SQLModel Session、Engine、模型客户端或向量库客户端。
- BR-025：只对超时和连接失败重试；参数、权限、余额不足、拒答和用户拒绝不重试。

## 异常场景

用户/资源不存在或越权；文件名、类型、内容或写入异常；解析结果为空；Embedding 模型、数量或维度异常；Milvus 连接、建表、检索、写入或删除异常；DeepSeek 未配置、请求失败或内容无效；SQLite 提交失败；历史引用 JSON 损坏。

## 本期不做

当前 Agent 迭代不实现管理员审批、复杂角色、前端、OCR、表格专用解析、混合检索、Rerank、知识图谱、多 Agent、邮件工具、后台任务队列、分布式和高可用部署。登录认证及知识库修改删除仍是后续需求；用户资料修改和账号删除不在计划内。

## 验收标准

- AC-001：Swagger 完成“用户→知识库→上传→解析→检索→会话→问答”。
- AC-002：重复解析不会累计 Chunk。
- AC-003：等于阈值保留，低于阈值过滤。
- AC-004：无依据时不调用 LLM。
- AC-005：来源包含 Chunk、文档、页码、摘录和分数。
- AC-006：删除后不能再召回，重复删除仍为 204。
- AC-007：第二个用户不能访问、解析或删除他人资源。
- AC-008：测试和编译通过，文档与代码一致。
- AC-009：FR-019 至 FR-021 实施后，知识库修改和删除只能作用于当前登录用户拥有的资源。
- AC-010：空知识库可以删除；包含文档或聊天会话的知识库必须拒绝删除，且所有关联数据保持不变。
- AC-011：模型可见的制度、余额和申请工具参数中不包含身份或知识库范围。
- AC-012：制度问题只检索当前 Agent 会话绑定的知识库，并返回与实际 Chunk 一致的引用。
- AC-013：余额工具只返回模型指定假期类型的当前用户余额；申请列表按创建时间倒序且最多返回最近 20 条；其他用户的数据返回 403 或资源不存在。
- AC-014：创建请假在批准前不产生申请；拒绝后仍无申请；同一批准重复提交只产生一条申请。
- AC-015：Agent 可以在同一 thread 中追问缺失参数，并在跨 HTTP 请求批准或拒绝后恢复。
- AC-016：用户可以通过 Swagger 完成制度问答、余额查询、申请草稿、拒绝、批准、申请查询和工具日志查看。
- AC-017：旧数据库升级后原有 RAG 数据可读取；Agent 单元、Graph、API、迁移测试与真实模型评测均有证据。

## 待确认

Agent 范围已经完成澄清，实施顺序为文档基线、迁移、业务领域、只读工具、Graph、人工确认、API、安全观测、评测和交付。`FR-019` 至 `FR-021` 保留稳定编号，不与 Agent 需求混用；最终简历验收前必须用 JWT 替换可伪造的 `X-User-ID`。

正式只读 Agent Graph 和 SQLite Checkpointer 已建立，但尚无 Agent API、人工确认和写入闭环，不能把 `FR-022`、`FR-026` 至 `FR-029` 整体写成已完成。
